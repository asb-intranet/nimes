# V119
Sauvegarder la base, tester la migration supabase/schema-v119.sql sur une copie, puis appliquer en production. Dans Vercel ajouter une variable Secret ASB_CREDENTIALS_KEY, valeur générée localement par `openssl rand -hex 32` (64 caractères hexadécimaux). Conserver la clé dans un coffre sécurisé, ne jamais la publier. Conserver SUPABASE_SERVICE_ROLE_KEY. Déployer. Tester création, lecture, modification, suppression et refus avec un compte salarié. Les anciens codes ne sont pas récupérables : les redéfinir. Le coffre contient des codes chiffrés AES-256-GCM, accessibles via le serveur après contrôle du rôle admin. Ne pas changer les mots de passe directement dans Authentication : le coffre ne serait plus synchronisé. Une perte de clé impose de redéfinir les codes. Ne pas partager les codes de comptes administrateurs. Le stockage réversible présente un risque supplémentaire par rapport au hachage seul.
